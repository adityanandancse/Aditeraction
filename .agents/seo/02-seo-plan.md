## 5. Technical foundation — schema, SSR, AEO/GEO

### 5.1 SSR / crawlability (stack-specific)
- TanStack Start SSR means **all copy renders server-side** → fully crawlable by Google and AI crawlers. **Keep it that way:** the WebGL particle hero must stay decorative; every headline, value prop and service description must be real SSR DOM text, never canvas-only or injected client-only.
- Static SVG fallback for the hero is good: no content is gated behind JS, and LCP is protected.
- One canonical URL form (no trailing slash, lowercase); self-referencing `<link rel=canonical>` on every page.
- `sitemap.xml` (all 12 page types, case studies as added) + `robots.txt` allowing major search + AI crawlers (see 5.4).

### 5.2 Schema markup plan per page type (JSON-LD)

| Page type | Schema |
|-----------|--------|
| Home | `Organization` + `ProfessionalService` (name, url, logo, `areaServed`, `sameAs` socials, `hasOfferCatalog` of the 6 services) |
| Services hub | `ProfessionalService` + `OfferCatalog` / `ItemList` of services |
| Service page | `Service` (+ `ProfessionalService` provider, `areaServed`) |
| Work hub | `CollectionPage` / `ItemList` of case studies |
| Case study | `Article` (+ `Organization` for client *only with permission* — else omit) |
| About | `AboutPage` + `Person` (founder Aditya, `sameAs` → `[PLACEHOLDER LinkedIn/socials]`) |
| Contact | `ContactPage` (+ `ContactPoint`) |
| All (except Home) | `BreadcrumbList` |

`areaServed`: express global reach (e.g. India + international) rather than a single locality — the studio is not a local-geo business, so **no `LocalBusiness`/address-based local SEO** unless a public business address is confirmed `[PLACEHOLDER]`.

### 5.3 AEO (Answer Engine Optimization)
- **Quotable, extractable statements**: lead each service page with one clear sentence an answer engine can lift (e.g. "Aditeraction designs the brand and writes the production code under one roof."). Clear H2/H3 structure, short declarative sentences (matches brand voice "say it straight").
- **FAQ blocks** (with `FAQPage` schema) on Home + each service page answering real buyer questions ("Do you design and build?", "Do you work with founders outside India?", "What does a project cost?" → honest ranges or "from `[PLACEHOLDER]`"). **Flagged:** FAQ content is a recommended addition beyond the 12-page scope; approve before build.
- Definition-style answers for "what is a design-and-engineering studio" to win People-Also-Ask / AI snippets.

### 5.4 GEO (Generative Engine Optimization) — from agency template checklist
- [ ] Original case studies with **specific, citable metrics** (load timings, build timelines) — gated on real data `[PLACEHOLDER]`.
- [ ] `Person` schema + `sameAs` for founder (entity authority).
- [ ] `ProfilePage`/`AboutPage` for the founder.
- [ ] Quotable expertise statements in each service description.
- [ ] Consistent entity info (name, logo, contact) across directories, LinkedIn, Instagram, Clutch/等 `[PLACEHOLDER profiles]`.
- [ ] `robots.txt` **allows** AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended) — confirm the studio *wants* AI visibility (recommended: yes).
- [ ] Consider `/llms.txt` summarising the studio + services for AI ingestion (recommended; low cost on this stack).
- [ ] Monitor AI citations (ChatGPT/Perplexity/Google AI Overviews) for "design and engineering studio" + brand terms.

### 5.5 Core Web Vitals targets (new-site baselines)
| Metric | Target |
|--------|--------|
| LCP | < 2.5s (static SVG hero fallback paints first; WebGL lazy-loads after) |
| INP | < 200ms |
| CLS | < 0.1 (reserve hero space to avoid shift when WebGL mounts) |
| Edge delivery | Cloudflare Workers SSR — exploit edge caching for static shells |

## 6. Content strategy (agency template)

- **Service pages**: min ~800 words each — value prop, method, deliverables, related work, "the team who delivers it" (founder-led), CTA. Voice per `brand-guidelines.md` (straight, sharp, specific; no "synergy/world-class/revolutionary").
- **Case studies**: min ~1,000 words — challenge → approach → build → measurable results → testimonial. **All facts `[PLACEHOLDER]`** until real projects confirmed.
- **About**: founder narrative, values (own the outcome / craft you can feel / design+code one discipline / say it straight / show don't claim). Must **not** reference any previous company of the founder.
- **E-E-A-T**: founder bio + credentials `[PLACEHOLDER]`; "show don't claim" → real shipped work, real numbers only.
- **Blog/Insights**: out of current scope (flagged in `01-site-architecture.md §8` as top future expansion).
